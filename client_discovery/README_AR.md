# استبيان احتياجات إخلاص POS — أسئلة 1.1.0

أداة مستقلة لفهم نشاط العميل وتحويل إجاباته إلى متطلبات وخطة قابلة للمراجعة. لا تتصل بقاعدة بيانات POS ولا تعدّل وظائفه، ولا تنفّذ الخطة المقترحة. مرجع مراجعة الكود: `000036742830d7dc37b684ff4c2a9a412c914150`؛ إصدار التطبيق `1.2.0+12`، مخطط البيانات 13.

## النسخة الحالية قبل التسليم

العميل لم يستلم التطبيق. المسار الأساسي لفهم شغله الحالي ومجهود كتابة الفواتير وما يتوقعه من التطبيق. التفاصيل الإضافية تظهر باختياره. أرسل **HTML فقط**؛ لا يحتاج العميل الحزمة أو أدوات التحليل. في الملخص يضغط «مشاركة النتيجة على واتساب» ثم يختار واتساب والمحادثة. عند غياب مشاركة الملفات يتاح تنزيل النتيجة وإرفاقها كمستند، أو نسخ الإجابات كاملة. المشاركة تستلزم اختيار العميل والإرسال داخل واتساب؛ لا تأكيد آلي للتسليم. بقيت الأدوات والقوالب السابقة للمراجعة الداخلية.

## إرسال الاستبيان للعميل

1. أرسل **`dist/ALIkhlas-Survey.html`** كمرفق، ومعه [دليل العميل](docs/CLIENT_GUIDE_AR.md). الملف كامل: لا يحتاج الملفات المجاورة أو تثبيت أدوات أو حساب أو إنترنت.
2. العميل ينزّل الملف ويفتحه بمتصفح كامل مثل Chrome أو Edge، ثم يختار «نبدأ الاستبيان». معاينة المرفقات داخل تطبيقات الرسائل قد تمنع JavaScript أو التنزيل؛ افتحه خارج المعاينة. على الهاتف استخدم «فتح باستخدام» المتصفح إن كان نظام الملفات يسمح به. عند منع نظام الهاتف فتح HTML، يمكن إتاحة **نفس الملف** من استضافة ملفات ثابتة موثوقة، دون خادم جمع إجابات؛ لم ننشر رابطًا عامًا في هذه المهمة.
3. يتحرك العميل على خطوات قصيرة؛ «مش متأكد» و«لا ينطبق» متاحان حيث يناسبان، وكل سؤال يمكن تأجيله. الميزانية اختيارية. المسار البسيط في المثال 27 سؤالًا نشطًا بدل59، والتفاصيل حسب اختيار العميل؛ لم نقس زمن الإكمال على مستخدمين.
4. الحفظ تلقائي في المتصفح إن كان يسمح به. قبل الإغلاق أو تغيير الجهاز، يضغط «حفظ ملف للاستكمال»/«تنزيل نسخة للاستكمال». للاستكمال من الملف يستخدم «استيراد ملف إجابات»؛ لا حاجة للإجابة من البداية.
5. في النهاية يراجع الملخص، وينزّل **ملف الإجابات JSON** و«تقرير للقراءة» HTML ويرجعهما لك يدويًا. JSON هو الأصل للتحليل، والتقرير للقراءة. تصدير مسودة ناقصة مسموح ويظهر النقص صراحة.

**لا توجد خدمة استقبال أو زر إرسال شبكي.** يمكن إرسال الملف عبر القناة المتفق عليها مع العميل. لا تجمع كلمات مرور أو أسماء/هواتف عملاء حقيقيين أو عقود أو مبالغ حساسة. اسم النشاط مستعار واختياري.

## الحفظ والخصوصية

- الإجابات في `localStorage` على نفس الجهاز والمتصفح ومسار الملف، بدون تشفير. الوضع الخاص، تنظيف المتصفح، تغيير الملف/المسار، وسياسات الهاتف قد تمنع بقاء البيانات. لا تعتمد على الحفظ المحلي وحده؛ نزّل JSON.
- عند فشل التخزين يظهر تنبيه دائم؛ تستمر الصفحة في الذاكرة والتصدير متاح. إغلاقها قبل التصدير قد يفقد آخر الإجابات. عند فساد النسخة المحلية يتاح تنزيلها للفحص قبل الاستبدال.
- تغيير الإجابة قد يخفي أسئلة: تُحفظ الإجابات القديمة وتُصدَّر ولا تُستخدم في الاستنتاجات أثناء اختفائها. يوضح التقرير ذلك.
- الاستيراد يستبدل الاستبيان الحالي بعد التحقق والتأكيد، ولا يدمج ملفات عملاء مختلفين. نزّل النسخة الحالية أولًا. الملفات غير الصحيحة لا تستبدلها.
- لو الجهاز مشترك، نزّل النسخة وتأكد منها ثم استخدم «مسح المحفوظ من الجهاز». الملفات التي نزلتها لا تُحذف تلقائيًا.
- CSP يمنع الاتصالات الخارجية؛ لا خطوط أو مكتبات أو تحليلات من الإنترنت. لا ادعاء بتشفير أو حماية من شخص لديه وصول لحساب الجهاز.

## استلام النتائج وتحليلها في Codex

ارفق `alikhlas-answers-….json` وقل:

> حلّل ملف الإجابات باستخدام `client_discovery` ومرجع قدرات المشروع، وراجع الفجوات على الكود الحالي إن اختلف الـcommit. افصل أقوال العميل عن الاستنتاجات والمقترحات، ووضّح الناقص والتعارضات. أنتج تقريرًا وخطة واختبارات قبول للمراجعة، ولا تنفّذ وظائف POS أو ترحيلات قبل اعتماد الخطة.

يمكن أيضًا إعادة استيراد JSON داخل HTML نفسه لعرض الملخص وتنزيل التقرير دون أي أدوات. وللمطور فقط، Node 18+ بدون حزم خارجية:

```sh
node client_discovery/tools/analyze.mjs path/to/answers.json --out /tmp/client-needs
```

المخرجات: `normalized-answers.json` يحفظ الأصل وحقوله الإضافية، و`analysis.json`، و`requirements-report.md`، و`requirements-report.html`، و`development-plan.md`. الأداة ترفض الكتابة فوق تقرير موجود إلا بـ`--force`، ولا تغيّر ملف الإدخال. لا تُطبّق ترحيلات أو اتصالات خارجية.

## الملفات

| الملف | الغرض |
|---|---|
| `dist/ALIkhlas-Survey.html` | الملف الوحيد الذي يحتاجه العميل |
| `data/questionnaire.json` | 95 تعريف سؤال بمعرفات ثابتة، اختيارات، هدف كل سؤال وشروط ظهوره |
| `docs/QUESTIONS_AR.md` | نسخة الأسئلة والشروط القابلة للمراجعة |
| `data/capabilities.json` و`docs/PROJECT_CAPABILITIES.md` | قدرات التطبيق وحالتها وأدلة الكود وحدوده والعيوب المعروفة |
| `schemas/*.schema.json` | JSON Schema للإجابات وتعريف الاستبيان |
| `lib/engine.js` | محرك مشترك للتحقق والشروط والتحليل والتقارير، في المتصفح والأداة |
| `templates/*.md` | قوالب تحليل الفجوات والخطة المرحلية |
| `docs/QUESTIONNAIRE_DESIGN.md` | منطق القرارات والإصدارات وحدود الاستنتاج |
| `examples/` | ثلاثة ملفات إجابات **افتراضية** مع تقاريرها وخططها |
| `tests/` و`docs/TEST_RESULTS.md` | الاختبارات والأدلة وحدود التحقق |

## تطوير الأداة واختبارها

```sh
node client_discovery/tools/examples.mjs
node client_discovery/tools/build.mjs
node client_discovery/tools/build.mjs --check
node client_discovery/tests/engine.test.cjs
python client_discovery/tests/schema_test.py
python client_discovery/tests/browser_test.py
```

آخر أمرين للمطور فقط: الأول يحتاج `jsonschema`، والثاني Playwright وChromium المثبّتين في بيئة الاختبار. هذه **ليست تبعيات للعميل أو لتطبيق POS**. `package.json` لا يحتوي تبعيات. عدّل المصدر ثم أعد البناء؛ HTML الموزع مخرج مضمّن قابل للتشغيل وحده. اقرأ نتائج الاختبارات لمعرفة قيود سياسة `file://` في البيئة الحالية، وعدم اختبار أجهزة هاتف فعلية.
