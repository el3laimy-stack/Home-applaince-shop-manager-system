# تقرير تحليل الاحتياجات — قالب للمراجعة

- رقم الاستجابة / إصدار الصيغة والأسئلة / تاريخ الاستلام:
- commit مرجع الكود / إصدار العميل إن عُرف / اختلاف النسخ:
- مصادر الأدلة: ملف JSON الأصلي، كتالوج القدرات، تحقق الكود الحالي.
- حالة الوثيقة: مسودة تحتاج اعتمادًا. لا تنفيذ تلقائي.

## أ. الملف التشغيلي — ما قاله العميل

نوع النشاط، الخدمات، نطاقات الأصناف والفواتير والأطراف والموظفين والأجهزة والفروع، المواسم. لكل حقيقة: معرف السؤال + الإجابة الأصلية + هل هي نشطة أم محفوظة من مسار سابق. لا تحوّل عدم الإجابة إلى «غير مطلوب».

## ج. المشكلات الفعلية

| المشكلة ودليلها | التكرار | الأثر | عاقبة عدم الحل | أولوية العميل | مثال غير حساس | الثقة |

## هـ. القرارات — ما يقترحه النظام

ما يُجرّب كما هو، وما يُبسّط، وما يُحسّن، وما يضاف بعد الاعتماد، وما طلب العميل عدم تنفيذه. افصل عيوب الكود المثبتة عن مشكلات أبلغ عنها العميل.

## و. Android والمزامنة

قارن سطح المكتب، لوحة مالك للقراءة، Android مكمل، Android كامل، بيانات مشتركة وخادم. اذكر الدور/المهمة/الكتابة/انقطاع الشبكة/الخصوصية/الاعتمادية/التعقيد والجهد النسبي والأثر المعماري. ربط طابعة لا يعني مزامنة بيانات، ووجود أكثر من جهاز لا يعني بيانات مشتركة. اذكر سبب الترشيح ودرجة الثقة والبدائل المستبعدة وشروط تغيير القرار.

## ز. غير محسوم

الأسئلة الناقصة، الاختيارات «غير متأكد»، التعارضات والإجابات التوضيحية، الافتراضات، الملاحظات الحرة، اختلاف نسخة المشروع أو صيغة الاستبيان. لكل نقطة: سؤال المتابعة والقرار المتوقف عليها.

## ملحق حفظ الأصل

ملف الإجابات الأصلي محفوظ، والحقول غير المعروفة والمخفية مذكورة ولا تُستخدم كدليل حالي. لا تلخص التقرير بطريقة تُسقط إجابات أو امتدادات. ضع الخطة وفق القالب المصاحب واعتمدها قبل أي تنفيذ.
