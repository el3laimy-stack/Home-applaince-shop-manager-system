## توافق البيانات

- الترقية من الإصدارات 3 حتى 11 لها اختبارات بقواعد تحوي فواتير ووردية مفتوحة وإيصال عملية محفوظة.
- لا تغير الترقية القيود والأرصدة والكميات ومعرّفات المستندات أو بصمات الطلبات.
- الفواتير القديمة تثبت اسم الصنف وباركوده الموجودين وقت الترقية، ويظهر التنبيه الموافق في التفاصيل وPDF. لا يُدّعى استعادة اسم تاريخي لم يكن محفوظًا.
- الورديات المغلقة تبقى كما هي. الوردية المفتوحة وقت الترقية تحمل حصيلتها السابقة؛ بعدها تستخدم حد القيود، مع طلب مراجعة النقد الفعلي عند الإغلاق.
- تنسيق ZIP يظل الإصدار 1. قد تُرفض حزمة قديمة ناقصة الصور؛ وجود ملفات المصدر على الجهاز لا يعوض مرفقات غير موجودة داخل الحزمة.
- العودة للإصدار السابق تحتاج قاعدة ما قبل الترقية؛ أي عمليات أحدث تحتاج حفظًا ومعالجة قبل الرجوع.

## التحقق

- Flutter `3.44.2` وDart `3.12.2`، بما يطابق CI.
- التحليل: ناجح دون ملاحظات.
- قفل العمليات: ناجح، بما يشمل تحرير القفل بعد إنهاء العملية المالكة.
- اختبارات العيوب والترقية والحدود العددية: ناجحة.
- المجموعة الكاملة النهائية: **227 اختبارًا ناجحًا، دون فشل**، بالأمر `flutter test --no-pub --reporter expanded --concurrency=2` في 8 دقائق و19 ثانية.
- محاولة بناء Linux المحلي توقفت عند غياب CMake. بناء Windows وحزم التثبيت يحتاج تشغيل CI.
- الرفع للفورك وإنشاء فرع عبر GitHub API رُفضا بـ403 (`Resource not accessible by integration`)؛ الحساب نفسه يملك صلاحية إدارة الريبو. يلزم تصحيح تفويض التطبيق المرتبط قبل رفع الفرع وتشغيل CI.
