# الشاشة الثالثة: يومية المحل

الفرع `feat/dashboard-liquid-glass-review` مبني على مراجعة تسجيل الدخول. النطاق: اليومية والتنقل المشترك اللازم لعرضها. لم تُعدّل خدمات المحاسبة أو مخطط البيانات أو وظائف البيع والشراء والتقارير. مكوّنا نقص المخزون والقيود المستخدمان في التقارير حُفظا كما كانا، واستُخدمت مكونات محلية منفصلة لليومية.

## الفحص والمعالجة

| المشكلة المؤكدة | المعالجة |
| --- | --- |
| عند 1024×720 ونص 125% يختفي ربح اليوم أسفل النافذة | مبيعات اليوم وصافي ربحه وعدد فواتيره ظاهرة قبل التمرير، مع إبراز «بيع جديد» |
| الربح اليومي والتراكمي يظهران دون تمييز كافٍ | فصل «نتائج اليوم» عن «أرصدة المحل الحالية» و«صافي الربح التراكمي» |
| التنبيهات أربعة أعمدة ثابتة، وأسفل الشاشة عمودان بارتفاع ثابت | توزيع بارتفاع طبيعي يتكيف مع العرض وتكبير النص، وتمرير واحد للمحتوى |
| التنبيهات لا تفتح الإجراء المناسب | المخزون والأقساط والنسخ تُفتح مباشرة؛ لا تُدّعى فلاتر لم تُنفذ |
| اسم ملف النسخة لا يفيد العميل في معرفة وقت الحفظ | عرض وقت النجاح المسجل، أو التصريح بأن الوقت غير متاح، أو عدم وجود نسخة؛ دون ادعاء اختبار استعادة |
| إجمالي المدين في القيد قد يُفهم كقيمة فاتورة أو نقدية | السجل المحاسبي ثانوي قابل للفتح، ومعاينة الوصف والتاريخ دون مبلغ القيد المركب |
| ملء النقد الفعلي بالمبلغ المتوقع عند الإغلاق | المتوقع معلومة مستقلة، والمدخل الفعلي فارغ ويتطلب مبلغًا صريحًا، حتى للصفر |
| تغيير تخطيط التنقل عند تصغير النافذة يفقد حالة المحتوى | مضيف ثابت للمحتوى يحفظ حالته، مع اختبار استكمال حوار الوردية عبر تغيير الحجم |
| الخطأ غير المتوقع في الوردية لا يُشرح، وخطأ التحميل يعرض استثناءً تقنيًا | رسالة مفهومة، وإتاحة التعافي، واستمرار مسار مراجعة الطلب المالي السابق؛ خطأ التحميل له إعادة محاولة |

اختلاف النقد المتوقع للوردية عن رصيد الخزينة التراكمي قائم في خدمات التطبيق: المتوقع يعتمد على الرصيد الافتتاحي وحركات الوردية. لا تُوحّد الواجهة الرقمين ولا تغيّر الحسابات.

## المراجعة المستقلة

راجع Agent مستقل متخصص في وضوح واتساق واجهات iOS/Liquid Glass الصور الأساسية والتفصيلية والكود، للقراءة فقط. اعتمد اليومية والتنقل الضروري لها بصريًا دون Blocker أو Major متبقية. أُغلقت ملاحظاته حول اتجاه الأسهم ورمز فشل تحميل البيانات والحدود الداخلية للأقسام ووضوح رسالة النسخ كاملة. هذا اعتماد مراجعة مستقلة، وليس اعتمادًا من Apple أو اعتمادًا لبقية شاشات التطبيق.

## الاختبارات

`dashboard_review_test.dart` يغطي 16 حالة ناجحة:

- أربعة عروض أساسية: فاتح/داكن، 1280/1024، مع إثبات ظهور المؤشرات والبيع قبل التمرير.
- مطابقة المبيعات والربح وعدد الفواتير للقيود الفعلية في قاعدة اختبار مؤقتة؛ فتح تفاصيل اليوم والأرصدة والسجل.
- حالتان فارغتان بعرض 360؛ الوصول للمحتوى السفلي بالتمرير.
- عرض 320 ونص 200% مع أسماء طويلة ومبالغ كبيرة وسالبة دون تصغير قسري للأرقام.
- قائمة التنقل عند 320 و200%، والقسم المحدد، والمساعدة والخروج ونهاية التمرير.
- الأفعال السريعة والتنبيهات تفتح وجهاتها الصحيحة على عرض سطح المكتب.
- وقت النسخ، وغياب الوقت، وغياب النسخة، والتحذير وإجراء الإعداد.
- قائمة النواقص تشرح المتاح وحد التنبيه، وتصرّح بأن المعاينة أول خمسة أصناف، مع فتح المخزون الكامل.
- الوردية: التحقق من الفراغ والإلغاء، ثم الفتح؛ المتوقع مقابل المبلغ الفعلي عند الإغلاق، وتصغير النافذة وإظهار مساحة لوحة المفاتيح أثناء الحوار. حُفظ فعليًا 90 جنيهًا مقابل 100 متوقعة.
- منع الإرسال المكرر في الوردية، ومعالجة استثناء تخزين وإتاحة إعادة المحاولة دون تكرار وردية.
- خطأ التحميل يعرض رسالة آمنة وإعادة المحاولة تنجح مع بقاء الجلسة.
- حالة التحميل تنتظر البيانات ثم تعرض اليومية.

كُشف في الاختبار أيضًا تعارض حفظ موضع `SelectableText` مع حالة `ExpansionTile`، وعولج بمفاتيح مستقلة. جرى فصل حالة فتح حوار الوردية عن انتظار الحفظ حتى لا يظهر تحميل مستمر أثناء انتظار إدخال المستخدم.

```sh
cd Frontend/alikhlas_pos
flutter test --no-pub test/v2/dashboard_review_test.dart
flutter test --no-pub test/v2/audit_navigation_test.dart test/v2/invoice_draft_ui_test.dart test/v2/financial_recovery_ui_test.dart
flutter test --no-pub test/v2/liquid_glass_test.dart test/v2/v2_golden_test.dart
flutter analyze --no-pub
```

المراجع البصرية المتغيرة مقصورة على `dashboard_liquid_glass.png` و`ios_dark_dashboard.png`. مراجع البيع والتقارير والإعداد والدخول محفوظة دون تغيير، وتُقارن دون خيار تحديث بعد تثبيت اليومية.

النتيجة النهائية: **42 اختبارًا مختلفًا ناجحًا**: 16 لليومية، و7 للتنقل والمسودات ومراجعة الطلب المالي السابق، و19 للثيم والمراجع البصرية. نجح `flutter analyze --no-pub` دون ملاحظات. لا يشمل العدد مرات تحديث المراجع أو إعادة تشغيل الحالة نفسها أثناء الإصلاح.

## حدود القبول

الصور والاختبارات محلية على Linux داخل محرك Flutter، ومساحة لوحة المفاتيح محاكاة. لم يُختبر جهاز Windows فعلي أو طابعة فعلية في هذه الدفعة. التكيف مع العرض الضيق يخص اليومية والقائمة؛ بقية الأقسام تُختبر عند التنقل إليها على عرض سطح المكتب وتُراجع لاحقًا. لا بيانات عميل فعلية أو تبعيات أو ترحيل قاعدة بيانات، ولا دمج أو إصدار تسليم ضمن هذه المراجعة.
