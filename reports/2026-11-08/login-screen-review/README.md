# الشاشة الثانية: تسجيل الدخول

الفرع: `feat/login-screen-liquid-glass-review`، مبني على فرع مراجعة إعداد المحل. النطاق: تسجيل الدخول وحوار «نسيت كلمة المرور؟» المرافق له. لم تُعدّل شاشة تغيير كلمة المرور الافتراضية أو لوحة المتابعة أو قاعدة البيانات وخدمات المصادقة.

## الفحص والمعالجة

| المشكلة السابقة | المعالجة |
| --- | --- |
| اسم التطبيق هو العنوان الأكبر ووصف البداية تقني | عنوان واضح «تسجيل الدخول»، علامة مختصرة ووصف عملي، بنفس مفردات شاشة الإعداد |
| البطاقة تلامس حواف العرض الضيق ولا يوجد تمرير آمن | هوامش آمنة وبطاقة بعرض أقصى 480، وتمرير مستقل مع مساحة لشريط التمرير |
| تسميات الحقول تتغير مع التركيز ولا يوجد إظهار للسر | تسميات ثابتة، قيم LTR، إظهار وإخفاء مع الحفاظ على النص والتركيز |
| كل محاولة فارغة تصل للمصادقة | تحقق محلي من الحقول الفارغة فقط، دون فرض حد طول جديد على كلمات المرور القديمة |
| إعادة Enter قد ترسل أكثر من طلب، والاستثناء يترك التحميل معلقًا | منع الطلب المكرر، تعطيل الإجراءات أثناء الانتظار، وtry/catch/finally مع الاحتفاظ بالمدخلات وإتاحة المحاولة |
| رسالة المصادقة لا تُميّز بصريًا ولا تُزال عند التصحيح | رسالة واضحة داخل لوحة تنبيه قابلة للإعلان لقارئ الشاشة، وتمرير إليها وإزالتها عند تعديل المدخلات |
| الاستعادة غير قابلة للتمرير ويمكن إغلاقها قبل حفظ الرمز الجديد | حوار قابل للتمرير، تحقق بجانب الحقول، منع الإغلاق أثناء الحفظ وبعد إصدار الرمز حتى إقرار الحفظ، ونسخ حرفي للرمز باتجاه LTR |
| زر الاستعادة «تأكيد» غير محدد | «استعادة الدخول»، مع توضيح أنه يغيّر كلمة المرور ويصدر رمزًا جديدًا |

اسم الدخول `owner` جاهز وقابل للتعديل، والتركيز الأولي على كلمة المرور لتقليل الخطوات اليومية. حقل اسم المستخدم يوضح الفرق بين اسم الدخول والاسم الشخصي. لا يُعرض سر افتراضي للمستخدم.

## المراجعة المستقلة

راجع Agent مستقل متخصص في وضوح واتساق الواجهات صور قبل وبعد، والحالات الأساسية والأخطاء والانشغال والاستعادة والعرض الضيق وتكبير النص. راجع الكود للقراءة فقط. النتيجة: اعتماد بصري لتسجيل الدخول وحواره، دون Blocker أو Major متبقية. أُغلقت ملاحظات ظهور الأزرار المعطلة، وتمرير آخر رابط فوق لوحة المفاتيح، وتوضيح اسم إجراء الاستعادة.

تحسين اختياري غير مانع: موازنة أسطر مجموعات رمز الاستعادة على العرض الضيق. النص المنسوخ محفوظ حرفيًا. هذه مراجعة بمعايير مستلهمة من iOS وليست اعتمادًا من Apple.

## الاختبارات

نجحت الحالات الـ14 في `login_screen_review_test.dart`:

1. أربع حالات أساسية: فاتح/داكن، 1024/360، وتكبير نص 125%.
2. رفض الحقول الفارغة محليًا دون استهلاك محاولات الدخول.
3. التركيز الأولي وإظهار السر وEnter وTab مع بقاء النص.
4. طلب دخول واحد عند الإرسال المكرر، وتعطيل الإجراءات أثناء الانتظار، ثم تصحيح الخطأ والدخول.
5. استثناء تخزين غير متوقع مع بقاء المدخلات ونجاح إعادة المحاولة.
6. عرض 320×520 ونص 200% ومساحة لوحة مفاتيح 180، مع وصول زر الاستعادة كاملًا فوقها.
7. التحقق المحلي من الاستعادة والتطابق، والإلغاء مع بقاء مدخلات شاشة الدخول.
8. منع تكرار الاستعادة والإغلاق بالخارج وEscape والرجوع أثناء الحفظ وبعد إصدار الرمز؛ نسخ حرفي، وإقرار ثم دخول بالسر الجديد.
9. فشل تخزين الاستعادة وإعادة المحاولة أثناء ظهور مساحة لوحة المفاتيح.
10. استمرار الحساب القديم في فرض تغيير السر وحفظ رمز الاستعادة قبل فتح لوحة المتابعة.
11. التفاف رسالة الحظر على العرض الضيق وبقاء المدخلات ورسالة الحظر عند تبديل الثيم.

نجح أيضًا اختبار الاستعادة الموجود مسبقًا في `v2_app_test.dart` واختبار حظر محاولات الدخول في `reliability_hardening_test.dart`. تغيير الاختبار الموجود يقتصر على تسمية زر الاستعادة الجديدة. `flutter analyze --no-pub` دون ملاحظات.

نجح فحص الرجوع أيضًا: 11 حالة لشاشة الإعداد، و3 حالات لخدمة الاستعادة، و14 حالة للثيم، بما فيها مقارنة المراجع البصرية. بذلك نجح **44 اختبارًا مختلفًا** إجمالًا. حُدّث المرجع البصري `ios_dark_login.png` لهذه الشاشة فقط، ثم جرى التحقق منه دون خيار التحديث. بقيت مراجع الشاشات الأخرى كما هي.

```sh
cd Frontend/alikhlas_pos
flutter test --no-pub test/v2/login_screen_review_test.dart
flutter test --no-pub test/v2/v2_app_test.dart --plain-name 'owner can recover access'
flutter test --no-pub test/v2/reliability_hardening_test.dart --plain-name 'login throttling'
flutter test --no-pub test/v2/first_screen_review_test.dart test/v2/recovery_access_test.dart test/v2/liquid_glass_test.dart
flutter analyze --no-pub
```

## حدود التحقق

الفحص محلي على Linux داخل اختبارات Flutter، مع محاكاة مساحة لوحة المفاتيح؛ لا يساوي اختبار لوحة مفاتيح هاتف فعلية أو قبول Windows ميداني. العرض الضيق المعتمد هنا خاص بالدخول والاستعادة. اختبارات إنهاء الدخول تعيد العرض إلى 1024 قبل لوحة المتابعة؛ إعادة تصميمها وفحصها مهمة تالية. الشاشة القديمة لتغيير السر اختُبرت وظيفيًا على عرض سطح المكتب فقط ولم يُمنح لها اعتماد بصري ضمن هذه الدفعة.

لا توجد تبعيات جديدة أو تعديلات على مخطط البيانات أو ترحيل لبيانات العملاء. لا دمج أو إصدار تسليم ضمن هذه المراجعة.
