# عقود البيانات والفحص المستقل

المخطط الحالي 16 ؛ ترقية 14 للأنواع والتفرّد، 15 للإيصالات، 16 لاعتماد الدفتر. أساس المصدر 3957a7deec339ae8e1a547428887e285f613cc93. لا تعديل لقاعدة محل فعلية ولا نشر.

عقد `schema_contract_v16.json` مولد من بيانات Drift:28 جدولًا و 204 أعمدة، مع أصل الإصدار ونوع التخزين و NULL والمراجع. احتُفظ بعقد 13 السابق للأثر التاريخي. العقد JSON للتشخيص؛ تعريفات SQL المرجعية في `lib/v2/data/database_*_sql.dart` ومقارنات قبول الترقية، و snapshots في `test/fixtures/`.

الفحص الخام قبل DDL وقبل قبول الترقية/الاسترجاع يقرأ typeof قبل نماذج Dart ، ويستخدم BigInt للتراكم والضرب وحدود int64. يعالج الأنواع والتفرّد والمراجع والأطراف والبنود والمدفوع وقت الإصدار والدفتر والمرتجعات والخطط. شروط القبول التفصيلية وحدودها موثقة في `SCHEMA_AND_RECOVERY_AR.md`. Python أداة تشخيص جزئي للقراءة فقط؛ ليست بوابة القبول البرمجية.

## قاموس دلالات الأعمدة

| المجموعة | الوحدة/المعنى | مصدر الحقيقة وسياسة التعديل |
|---|---|---|
| معرفات المستندات العددية والمراجع *_id | عدد صحيح يحدد صفًا؛ NULL حيث يصرح المخطط فقط | لا يعاد ترقيمها أثناء الترقية أو الاسترجاع؛ checkout_drafts.id نص، و app_settings.key نص، وليسا معرفين عدديين |
| مبالغ *_minor | قروش، integer موقّع 64 بت | الحساب الوسيط دقيق؛ لا double أو قص عند تجاوز المجال |
| products.stock_qty | كمية وحدات صحيحة | رصيد مخزن؛ يحدّث مع حركة المخزون والقيد في معاملة ويطابق السلسلة |

| qty في البنود | وحدات صحيحة موجبة | مستند تاريخي بعد التسجيل؛ التصحيح/الرد عبر مساراتهما |
| stock_movements.qty_delta و balance_after | تغير كمية موقع عليه والرصيد بعده | السلسلة بترتيب id ؛ لا ترتيب بالتاريخ وحده عند تغير ساعة الجهاز |

| ledger_lines.debit_minor/credit_minor | سطور الدفتر | مصدر الأرصدة المحاسبية؛ اتزان كل قيد ومطابقة المستندات مطلوبان |
| shifts.opening_ledger_entry_id | حد تسلسل وقد يكون صفرًا | ليس بالضرورة ملكية لقيد؛ لا تضف FK من دون تغيير العقد |

| الحقول الزمنية Drift | integer timestamp وفق تحويل Drift الحالي | due_date موعد استحقاق تجاري، وليس تاريخ إنشاء المستند؛ يجب اختبار المناطق الزمنية عند التطوير |

الأعمدة الدقيقة وأسماؤها الفعلية في ملف JSON. القيود المنفذة موثقة في مخطط SQL واختباراته؛ القاموس يشرح الدلالات. السالب في النقدية/المحفظة المصرح به ليس مخالفة تلقائية. الصفر قد يكون مشروعًا لبعض التكاليف/المبالغ؛ لا يطبق حظر عام.

## سجل الروابط المنطقية

## عقود نتائج إيصالات العمليات

المفتاح الكامل `operation.<namespace>.<operationKey>` لا يجزأ عند أول نقطة؛ namespaces مثل shift.open تحتوي نقاطًا. البصمات التاريخية لا يعاد حسابها أو استبدالها. المفاتيح غير المقروءة تظل حواجز؛ لا تصلح الأداة محتواها أو تعيد تشغيل العملية.

| namespace | معنى قيمة النتيجة المحفوظة تحت id | بديل تاريخي معروف |
|---|---|---|
| sale | sale_invoices.id | saleId |
| purchase | purchase_invoices.id | purchaseId |
| sale_return / purchase_return | معرف مستند المرتجع المقابل | — |
| opening_stock | products.id | — |
| inventory_adjustment / opening_balance | معرف مستند الجرد / الرصيد الافتتاحي | — |
| financial_correction / financial_correction_reversal | معرف التصحيح / عكسه | — |
| expense | expenses.id | — |
| installment.customer / installment.supplier | ledger_entries.id للتحصيل/السداد | — |
| shift.open / shift.close | shifts.id | — |
| product_csv_import | **عدد صفوف مستوردة، وليس product ID** | — |

في الكود الحالي العدد موجب؛ استيراد قائمة فارغة مرفوض. فحص الأداة لصيغة الإيصال يطابق الحد الأدنى الحالي: fingerprint نص ونتيجة integer موجب. لا يثبت صحة البصمة بالنسبة للطلب الأصلي لأن الأداة لا تمتلك ذلك الطلب. نُقلت الإيصالات إلى operation_receipts مع raw_payload الأصلي و ready/blocked. المستودع يفحص الجديد والقديم معًا؛ لا يتجاوز إيصال جديد تعارضًا قديمًا. الكتابة الجديدة إلى الجدول فقط داخل المعاملة المالية.

## استخدام الأداة

المتطلب Python 3.10+ ومكتبة sqlite3 القياسية. افتح **نسخة DB مستقلة أُنشئت من التطبيق**، وليس ملف القاعدة الحي أو نسخة ملفية من قاعدة مفتوحة. ZIP تحتاج مسار استرجاع التطبيق ولا تقبلها هذه الأداة. أوقف أي عملية تكتب إلى نسخة الاختبار نفسها طوال الفحص.

```bash
cd Frontend/alikhlas_pos
python3 tool/database_preflight.py --snapshot /path/to/standalone-backup.db
python3 -m unittest discover -s tool -p 'test_database_preflight.py' -v
```

تفتح الأداة الملف بـ mode=ro و immutable=1 و query_only ؛ لا تنشئ قاعدة عند غياب الملف، ولا تصلح صفوفًا، ولا تكتب تقريرًا تلقائيًا إلى القرص. immutable يتجاهل WAL ، لذا ترفض الأداة ملفًا له sidecar باسم -wal أو -journal بدل إعطاء قراءة ناقصة. افتراض نسخة ثابتة شرط، وليس آلية قفل لحماية القاعدة الحية.

رمز الخروج 2 يعني blocked أو مدخلًا غير صالح، و 0 يعني اكتمال **التشخيص الجزئي فقط** وقد يحتوي تحذيرات. scope في JSON يصرح بأنها ليست migration acceptance. يعرض التقرير codes و table و column و count دون أسماء العملاء أو الأرقام أو hash كلمات المرور أو محتوى الإيصالات أو مسار الملف.

الفحوص الحالية: سلامة SQLite ، وجود جداول/أعمدة الإصدار، نوع التخزين و NULL والـ boolean ، المفاتيح الأجنبية المعلنة، بعض الروابط النصية والمرتجعات، تكرار أهداف الخطط/الافتتاحيات والورديات، qty الموجب، فيض backfill القديم، سطور الدفتر والحسابات واتزان كل قيد وحدود مجموعه، وإيصالات العمليات.

ليست مكتملة: لا مطابقة شاملة للفواتير والمدفوعات/المخزون/الدفتر/الأطراف، ولا فحص كامل لأسعار السطور والحالات والدلالات، ولا تحقق من definitions الفهارس والمشغلات، ولا صحة مسودات JSON أو كل علاقات المخزون. لا تنتج baseline قبول منطقي للترقية. تبقى dataIntegrityAudit واختبارات Flutter والتدقيق الإضافي المخطط لها مطلوبة.

## سياسة التشخيص

- نوع/مرجع/قيد غير صحيح أو فيض: blocker في الأداة؛ احتفظ بالنسخة ولا تصلحها تلقائيًا.
- namespace مجهول أو صف blocked محفوظ: يبقى حاجزًا؛ لا يعاد تنفيذ العملية. وجود الحاجز لا يثبت فساد بقية المال.
- لا ملاحظات في Python: اكتمال تشخيص جزئي فقط. قبول الترقية يستخدم مدقق Dart الخام ومطابقة جميع الصفوف الأصلية والأعمدة وقيود المخطط.

الأداة لا تطابق كل تعريفات المشغلات أو كل محاسبة المستندات، ولا تفك مسودات JSON أو تختار قاعدة بديلة للتطبيق. اختبارات Python تصنع أشكالًا تشخيصية؛ اختبارات ترقية Drift تستخدم fixtures منفصلة موثقة. الملفات 3 و 6 أعيد بناؤها من تسلسل الترقية الأصلي، وبقية 3–13 من المصدر/generated metadata الأصلي حيث توجد commits مستقلة.
