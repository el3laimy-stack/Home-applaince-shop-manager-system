# ALIkhlas POS — خطة ترخيص Offline مرتبطة بجهاز واحد

## الهدف
- كل جهاز تجاري يحتاج ملف ترخيص موقّع من الناشر؛ النسخ العادي للبرنامج أو ملف الترخيص أو قاعدة البيانات لا يفعّل جهازًا مختلفًا.
- لا يحتاج التطبيق إلى إنترنت بعد استيراد الترخيص.
- لا يُخزَّن مفتاح التوقيع الخاص في التطبيق أو Git أو GitHub Secrets الخاصة ببناء تطبيق العميل.
- لا يوجد عملاء سابقون؛ يظل الدمج في main مؤجلًا حتى إصدار مفاتيح الإنتاج وتجربة التثبيت.

## نموذج الثقة
1. جهاز Windows يستخدم UUID الخاص بالنظام وبصمة MachineGuid (ولينوكس machine-id) لإنتاج SHA-256؛ المعرف الخام لا يخرج من الجهاز.
2. المسؤول يصدّر License JSON يحمل معرف الجهاز واسم العميل ومعرف الترخيص وتاريخ الإصدار وانتهاء اختياري.
3. المسؤول يوقع الحمولة القياسية بـ Ed25519 باستخدام مفتاح خاص محفوظ خارج المستودع.
4. التطبيق يحتفظ بالمفتاح العام المعلن أثناء بناء الإصدار ويتحقق من سلامة التوقيع والبصمة قبل عرض شاشة تسجيل الدخول.
5. التراخيص دائمة ما لم يحدد لها تاريخ انتهاء. الإلغاء عن بعد لا يمكن فرضه فوريًا بدون اتصال أو حد زمني.
6. النسخ والنسخ الاحتياطية تبقى متاحة لحامل البيانات ولا تُمسح عند فشل التفعيل.

## قيود معلومة
الحماية المحلية تردع النسخ التجاري الاعتيادي ولا تمنع تمامًا تحليل وتعديل النسخة التنفيذية. المستودع الحالي سبق نشره كـ MIT؛ تغيير رؤية المستودع لا يسحب الحقوق الممنوحة سابقًا. يتطلب منع إعادة توزيع الإصدارات الجديدة مراجعة سياسة الترخيص وملكية العناصر المضمنة.

## سياسة التوزيع
إصدارات CI غير المضبوطة بمفتاح عام للإنتاج تفشل في التفعيل؛ لا ينبغي توزيعها على العملاء. يزوَّد المفتاح العام فقط إلى بناء الإصدار؛ المفتاح الخاص يتواجد على جهاز الناشر.
